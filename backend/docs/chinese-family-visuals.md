# Prospective Chinese-family illustrations

The native prompt `official-account-generated-visual-prompt-v5-chinese-family`
adds contemporary Chinese-family learning, visibly elementary- or middle-school
children and an actively participating, reference-consistent Xiaosai protagonist.
The nearest explicit school-stage cue in the selected block takes precedence over
section/topic cues. Mixed or unspecified contexts choose a suitable school-age
group rather than requiring both groups. Parents/caregivers appear when useful,
not as a mandatory posed family cast. Child proportions, clothing and learning
props must be age-appropriate; toddlers and adultized children are excluded.

Only Xiaosai is the requested IP. V5 selects approved references whose trusted
manifest `VisualAsset.characters` set is exactly `{"xiao-sai"}`. Sai Xiansheng-only,
mixed and unknown references are excluded, regardless of names or semantic tags.
No character is relabeled and no alternate mascot is substituted. The existing
full41 catalogue admission and native-eligible comparison pool remain intact;
only V5's selection pool is filtered. The catalogue owner revalidates actual
asset/master/publication identity before text generation and all five selected
references before image-generation intent, also on resume. Missing or changed
Xiaosai inputs stop paid work without falling back to another character. Source
DTO/frozen preview serialization, master files and catalogue metadata are unchanged.
V5 retains native1536×1024 geometry, premium gouache/navy-teal-cream style, no text,
block-specific actions, generous margins, five scenes and the existing cover route.
Original news photographs, source/rights metadata and placement are unchanged.

New V5 prepared HTML also omits the visible descriptive paragraph beneath body
illustrations. Image `src`, `alt`, styles and bytes are retained; original-news
captions, credits, rights disclosures and source cards remain visible. The pure
V2 renderer retains its historical default; the prepared owner opts in only from
the validated homogeneous V5 visual evidence, not current settings or Article
metadata. V4 prepared HTML remains byte-stable. Local no-caption preview copies
do not alter previously uploaded drafts or fabricate a new model review.

No configuration surface is added. Once compatible code and migration0045 are
installed, the shared settings-based identity factory chooses V5 for newly created
native strict/observe Articles. Existing stored V4 Articles and frozen weekly
inputs replay V4 exactly; legacy non-native versions remain unchanged. Only the
closed planV4/promptV4-or-V5 pairs are valid. A single Article's generated proofs
must agree with its frozen prompt identity.

Migration `20260909_0045` extends `20260907_0043` and changes only the native
prompt allowlist CHECK. All original geometry, lease, provider, null and historical
plan guards remain. It is deliberately forward-only: V5 weekly checkpoint files
can be created before any database row, so empty SQL tables cannot establish safe
rollback. Keep V5-compatible code/schema; a later rollback needs separate review.
Do not combine this migration silently with another unshipped migration branch.

This change does not generate replacement images, add model calls or introduce
new age/IP rejection thresholds. Native-observe continues to record actual audit
outcomes without inventing acceptance. Prompt and fake-provider tests prove wiring
and bounds, not that every live raster satisfies the creative requirements.
Local implementation is not deployment or activation.
