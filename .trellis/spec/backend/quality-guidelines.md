# Backend Quality Guidelines

## Contract status

These are initial quality gates for Python 3.11/FastAPI. The local commands and first trusted
environment-shell tests now live in the paths linked below. CI remains a required follow-up when
continuous integration is introduced; it is outside the development-environment task.

## Required engineering patterns

- Use Pydantic v2 at HTTP, settings, and structured model-output boundaries.
- Type public functions and application/port interfaces; run a strict static type checker.
- Keep domain/application code independent of FastAPI, SQLAlchemy, and provider SDKs.
- Inject clocks, ID generators, repositories, and external adapters where deterministic tests need
  control; do not monkeypatch global time or clients by default.
- Version prompts, scoring configurations, parsers, embeddings, models, and policy rules.
- Make every stage input/output serializable and persist enough provenance to reproduce a verdict.
- Use UTC-aware instants and explicit business dates/timezones.
- Generate the OpenAPI schema deterministically for the frontend contract.

The implemented commands are owned by [`backend/pyproject.toml`](../../../backend/pyproject.toml)
and wrapped by the root [`Makefile`](../../../Makefile): `make backend-check` runs Ruff format
checking, Ruff lint, strict mypy across application and backend tooling scripts, and pytest with
coverage. Changing tools is acceptable only if the same gates remain and the task documents the
decision.

## Scenario: Local full-stack development environment

### 1. Scope / Trigger

This contract applies whenever a task changes the local interpreter, dependency manifests,
environment variables, Compose services, host ports, health shell, setup commands, or doctor
checks. These files form one cross-layer developer contract even though applications run on the
host and durable services run in containers.

### 2. Signatures

- Backend install: `conda run --name edu-ai python -m pip install -e "./backend[dev]"`.
- Frontend install: `npm ci --prefix frontend` from the committed lockfile.
- Infrastructure lifecycle: `make infra-up`, `make infra-status`, and `make infra-down`.
- Quality gates: `make backend-check`, `make frontend-check`, and `make check`.
- Contract generation: `make api-generate`; drift verification is part of `make frontend-check`.
- Smoke check: `make doctor` implemented by
  [`scripts/doctor.sh`](../../../scripts/doctor.sh).
- Health API: `GET /healthz` returns HTTP 200 and the typed body
  `{"service": str, "status": "ok", "environment": str, "timezone": str}`.
- Compose services: `postgres`, `minio`, and the idempotent one-shot `minio-init`.

### 3. Contracts

[`environment.yml`](../../../environment.yml) owns Python 3.11 and pip only;
[`backend/pyproject.toml`](../../../backend/pyproject.toml) owns Python application and development
dependencies; [`frontend/package-lock.json`](../../../frontend/package-lock.json) owns the npm
dependency graph. Do not duplicate package versions in Conda metadata.

The checked-in [`/.env.example`](../../../.env.example) defines safe local placeholders:

| Group | Keys | Contract |
|---|---|---|
| Application | `APP_ENV`, `APP_HOST`, `APP_PORT`, `BUSINESS_TIMEZONE`, `VITE_API_BASE_URL` | Host processes bind to loopback; business timezone defaults to `Asia/Shanghai` |
| PostgreSQL | `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_PORT`, `DATABASE_URL` | Local-only credentials and configurable host port |
| MinIO | `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`, `MINIO_API_PORT`, `MINIO_CONSOLE_PORT`, `MINIO_ENDPOINT`, `MINIO_BUCKET`, `MINIO_SECURE` | Local S3-compatible storage with a persistent named volume |
| AI platform | `AI_PLATFORM_BASE_URL`, `AI_PLATFORM_API_KEY` | Blank until a separately reviewed integration task |

When a host port changes, its consumer URL must change in the same edit: `APP_PORT` with
`VITE_API_BASE_URL`, `POSTGRES_PORT` with `DATABASE_URL`, and `MINIO_API_PORT` with
`MINIO_ENDPOINT`.

`.env` is ignored and must never be generated by a quality check. `make env-init` may create it
only when absent. `docker compose down` preserves the named volumes; volume deletion is never part
of a default target or doctor check.

### 4. Validation & Error Matrix

| Condition | Required result |
|---|---|
| Conda environment or backend dependencies missing | Doctor fails with `make setup-backend` remediation |
| `frontend/node_modules` or Vite missing | Doctor fails with `make setup-frontend` remediation |
| Compose cannot render | Doctor fails before inspecting services |
| Docker daemon unavailable | Doctor names Docker as unavailable; no alternate privileged path is attempted |
| PostgreSQL or MinIO is not healthy | Doctor names the service and points to `make infra-logs` |
| pgvector extension absent | Doctor fails instead of reporting database readiness |
| MinIO health endpoint or configured bucket absent | Doctor fails instead of reporting object-storage readiness |
| Provider credentials blank | Health and local quality checks still pass because provider calls are out of scope |

### 5. Good / Base / Bad Cases

- Good: a fresh clone creates `edu-ai`, runs both locked installs, starts Compose, and `make doctor`
  confirms the API shell, pgvector, MinIO health, and the bucket.
- Base: provider values remain blank while the health endpoint and all local checks pass.
- Bad: a script sources arbitrary `.env` shell content, logs secrets, binds durable services to all
  interfaces, uses floating image tags, or removes volumes during ordinary shutdown.

### 6. Tests Required

- [`backend/tests/test_health.py`](../../../backend/tests/test_health.py) must call the ASGI app
  through `httpx.ASGITransport`, assert the complete health body, and prove database credentials
  remain redacted in settings output.
- `docker compose config --quiet` must pass for the checked-in configuration.
- Infrastructure verification must query `pg_extension` for `vector`, call the MinIO live health
  endpoint, and stat the configured bucket through the pinned MinIO client image.
- `npm ci --prefix frontend`, `make backend-check`, `make frontend-check`, `bash -n
  scripts/doctor.sh`, and `git diff --check` must pass before completion.
- A credential scan must find no real API tokens, private keys, or non-placeholder provider keys.

### 7. Wrong vs Correct

#### Wrong

```yaml
services:
  postgres:
    image: postgres:latest
    ports: ["5432:5432"]
```

This floats the database image and exposes it on every host interface.

#### Correct

```yaml
services:
  postgres:
    image: pgvector/pgvector:0.8.1-pg16
    ports:
      - "127.0.0.1:${POSTGRES_PORT:-5432}:5432"
```

Use an explicit pgvector/PostgreSQL tag, configurable loopback binding, a named data volume,
health check, and idempotent `CREATE EXTENSION IF NOT EXISTS vector` initialization as implemented
in [`compose.yaml`](../../../compose.yaml).

## Test pyramid and required scenarios

### Unit tests

Cover pure normalization, source-tier eligibility, exact/semantic duplicate decisions, feature
normalization, weighted scoring, threshold behavior, veto precedence, claim coverage, validation
codes, retry classification, state transitions, and redaction. Use fixed clocks and deterministic
fixtures.

### Integration tests

Run against real PostgreSQL with pgvector, not SQLite. Test migrations, repository transactions,
job claiming under contention, idempotent inserts, vector/full-text filtering, evidence/brand
separation, and object/provider adapters through local fakes or recorded contract fixtures that do
not contain secrets.

### API and contract tests

Test status codes, stable error envelopes, `202` enqueue semantics, material-package responses,
and OpenAPI generation. CI regenerates frontend API types and fails on drift.

### Pipeline acceptance tests

At minimum, prove:

- a Tier C lead cannot become final factual evidence;
- duplicate content retains provenance and a seven-day event repeat is vetoed;
- a below-threshold day ends as `no_topic` without model/image generation;
- every accepted core claim has an eligible evidence binding;
- deterministic validation runs before LLM audit;
- an LLM auditor cannot invent evidence or override a hard veto;
- retryable failures back off and resume without duplicate side effects;
- retry exhaustion produces a visible terminal state;
- package output supports manual use and exposes no publishing endpoint.

### Front-to-back flow

Maintain one end-to-end test for the first vertical slice: enqueue or provide a candidate, create a
typed draft with evidence bindings, validate/audit using controlled adapters, create an image
artifact, expose the package, and exercise the frontend copy/download/source-link flow.

## Security review

- Treat source content and model output as untrusted; delimit it as data and never promote embedded
  instructions to system/developer prompts.
- Apply network timeouts, response-size limits, content-type checks, and an outbound-source policy
  to ingestion to reduce SSRF and resource-exhaustion risk.
- Sanitize rendered content and object keys/filenames.
- Keep secrets in deployment configuration, never source, prompts, logs, or API responses.
- Avoid collecting personal data about minors; if encountered, quarantine/redact it according to
  policy before any model call.
- Do not add social-platform publishing credentials, endpoints, or background actions.

## Review checklist

- Is the change in the correct API/application/domain/infrastructure layer?
- Are evidence and brand knowledge still separated in types, storage, and retrieval?
- Are scoring weights, thresholds, vetoes, prompts, and model versions persisted?
- Are all core claims bound to eligible evidence passages?
- Are external side effects idempotent and transactions short?
- Are failures typed as expected, retryable, or terminal rather than swallowed?
- Are logs structured, correlated, and free of secrets/content/PII?
- Are migration and OpenAPI drift checks included where contracts changed?
- Do tests cover the negative/policy path, not only the happy path?
- Does the product still require a human to publish?

## Forbidden patterns

- Blocking I/O inside async handlers or workers without an explicit thread/process boundary.
- `time.sleep()` in async code, unbounded retries, or unbounded model/source concurrency.
- `except Exception: pass`, boolean-only audit verdicts, or untyped provider dictionaries crossing
  adapter boundaries.
- LLM-generated scoring with no stored feature values/rules version.
- Using a second LLM pass as the only fact check.
- Mock-only tests for PostgreSQL locking, pgvector, migrations, or idempotency.
- Merging the first vertical slice without updating these greenfield specs with real examples.
