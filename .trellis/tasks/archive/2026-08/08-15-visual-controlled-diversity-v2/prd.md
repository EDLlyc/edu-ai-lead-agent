# 配图受控多样性 v2

## Goal

在保留赛先生、小赛既有角色身份、统一 3D 卡通风格和蓝白橙品牌语言的前提下，让每日独立新闻配图在场景、构图、镜头、角色组合和主题物体上产生可感知、可解释、可回放的变化，降低连续多日“同一张图只换主题”的重复感。

## Background and confirmed facts

- 用户明确选择保留统一的 3D 卡通风格，不进行 2D、信息图、杂志海报等跨风格轮换。
- 当前生产配置使用 Comfly、`gpt-image-2`、`brand-visual-selector-v1`，最多三张参考图；角色素材仍来自私有只读品牌目录。
- 当前 `visual-brief-v1` 只有六个固定类别；同一类别的场景、主动作、角色组合、文字层和构图指令固定，并且每次都要求小赛和赛先生同时出现。
- 参考素材排序主要由主题匹配分和人工优先级决定，运行 ID 只参与靠后的稳定排序；系统没有最近七天的场景、构图、镜头或参考素材使用历史。
- 2026-08-15 对生产库做的只读十日基线显示：23 张成功图片只有 18 个不同输出哈希、4 个不同视觉 brief、4 个类别、2 个场景和 4 个动作；13 张使用同一张“小赛和赛先生讨论”动作参考图，且没有成功图片使用 `style_reference`。
- 每条早/中/晚新闻拥有独立 copy run、图片 artifact 和素材包；本任务不得重新合并多条新闻。

## Requirements

### R1. 品牌身份稳定

- 保留赛先生、小赛的批准身份素材、统一 3D 卡通质感和蓝白橙品牌色。
- 多样性不能改变角色核心外形、角色名称、品牌标识或相对身份；不得用泛化猫头鹰、真人儿童或新角色替代。
- 身份参考可以重复；需要重点轮换的是动作、场景、构图、镜头、角色组合和主题物体。

### R1a. 固定且可读的配图文字标准

- 受控 v2/v3 图片只允许一个三层文字组，顺序固定为品牌签名 `赛先生科学`、按治理类别映射的
  短主标题、按同一类别映射的短副标题；不得把原始新闻标题、全文文案或模型自由生成文字直接
  画进图片。
- 三层文字使用深科学蓝圆角标题卡、克制的橙色品牌点缀和清晰字号层级，放在预留编辑区，
  不能遮挡角色面部、科学物体或主体动作。
- 只允许六类有限标题和副标题；不得出现第四行、旧版长品牌价值口号、关键词堆叠、伪文字、
  水印、二维码或其他字符。OCR 必须以相同顺序精确识别这三行，否则进入既有一次修复或类型化
  失败流程。
- 历史 v1 文字模式、metadata 形状和回放顺序保持不变。

### R2. 版本化视觉变化空间

- 新视觉 brief 必须从受控枚举中选择场景、构图、镜头、角色组合、主题物体和时段气质，不把原文、自由 Prompt 或模型文本直接当作视觉指令。
- 首版至少提供 10 个场景、8 个构图、5 个镜头和三种角色组合（小赛单人、赛先生单人、双角色），并覆盖机器人、AI、实验、天文、阅读、赛事、教室、研学等现有业务方向。
- 早报、午间观察、晚间精选拥有不同但同品牌的视觉节奏；同一新闻的选择必须确定、可解释并进入版本指纹。
- 视觉变化必须与已治理的新闻类别、实体或产品方向相符，不能为了变化添加新闻没有支持的主体或事件。

### R3. 七天受控去重

- 生成前读取最近七个自然日的成功图片历史，并在一个有界集合内避免重复使用相同的场景、构图、镜头、角色组合和动作/风格参考组合。
- 同一天同一时段的 0--3 条独立新闻不得获得相同的完整视觉组合。
- 不要求身份参考七天不重复；当候选空间不足时允许按明确优先级逐级放宽，并持久化放宽原因，不能随机失控或无限重试。
- 并发 worker、API 重放和 scheduler 对账必须得到一个数据库约束或锁保护的唯一预留结果，不能因竞态重复付费生成。

### R4. 成图相似度检查与一次修复

- 先对成功返回的 1024×1024 图片执行现有媒体、安全和尺寸校验，再计算不含秘密的感知指纹。
- 与最近七个自然日的成功图片做有界相似度比较；完全相同 SHA-256 必须判定为重复，近重复阈值必须通过受控 fixture 校准并版本化。
- 首次结果过于相似时，只允许使用另一个已预留的场景/构图/镜头组合自动重生成一次；第二次不得复用第一次的 provider 请求指纹。
- 第二次图片仍被判定为近重复时，只要事实、安全、角色身份、OCR 和输出完整性检查通过，就继续生成独立素材包并允许既有自动投递，同时持久化 `diversity_warning`；视觉相似不得升级为硬否决或 `review_required`。
- 相似度检查不是事实来源，也不能覆盖安全、OCR、角色身份或证据质量否决。

### R5. 审计、回放与兼容

- 持久化多样性策略版本、候选/选中视觉组合、最近历史摘要、放宽原因、感知指纹、相似结果和修复次数；API 只投影安全枚举、计数和结论。
- 新 Prompt、visual brief、selector、pipeline 和 similarity policy 使用新版本；历史 `visual-brief-v1`、旧图片、旧素材包和旧请求指纹继续可读取与回放。
- 相同业务输入、相同版本和相同历史快照必须得到相同视觉计划；重放不得再次调用供应商。
- 不记录原始 Prompt、供应商响应、私有素材路径、图片字节或凭据到日志/API。

### R6. 自动化和运维边界

- 不新增社交平台自动发布；企业微信仍只读取通过现有质量门的独立素材包。
- 配置默认关闭并支持快速回滚到当前 v1 视觉链路；API、scheduler、worker 和 dispatcher 的版本/阈值必须一致。
- 受控多样性总开关只能在图片 OCR 同时开启时启动；禁止因漏配 OCR 跳过三层文字验收。
- 前端只用于本地内部检查，不进入生产部署；如展示新信息，只展示安全的视觉变体和相似度结论。
- 不在普通测试中调用真实图片供应商或企业微信；真实验收最多使用一条批准新闻做一次有界图片 smoke，且需单独授权。

## Acceptance Criteria

- [ ] 给定同一类别的至少 10 条不同新闻，视觉计划产生不少于 8 个不同完整组合，同时全部保持统一 3D 品牌语言。
- [ ] 每个时段至少有 3 个可用构图变体，三时段的受控视觉节奏可以从持久化 metadata 和安全 API 投影中区分。
- [ ] 所有受控 v2/v3 Prompt、供应商拒绝恢复 Prompt 与 OCR allowlist 都只包含并精确校验
      `赛先生科学`、类别主标题、类别短副标题三行；历史 v1 metadata/回放不变。
- [ ] 最近七天存在重复历史时，选择器优先避开相同完整组合和动作/风格参考；候选耗尽时只按规定顺序放宽并记录原因。
- [ ] 同日同槽最多三条并发预留不会得到相同完整组合，不产生重复 provider 调用或重复成功 artifact。
- [ ] 完全相同图片和校准 fixture 中的近重复图片会触发一次不同视觉计划的修复；明显不同图片不会误触发。
- [ ] 相似度修复最多一次，身份、安全、OCR、证据和输出完整性门保持独立且优先。
- [ ] 第二次仍近似但其他质量门通过时，最终 artifact/package 保持成功并带安全的 `diversity_warning`；不会产生第三次供应商调用，也不会阻断企业微信自动投递。
- [ ] 历史 v1 artifact/package/API 回放不变，新版本的请求指纹与旧版本隔离。
- [ ] 受影响单元、真实 PostgreSQL 集成、迁移、API contract、Compose、Doctor、后端和前端质量门全部通过。
- [ ] 生产启用前有明确的开关、回滚步骤、十日基线和启用后七日观测指标；没有真实 provider/企微调用混入普通门禁。

## Out of Scope

- 重新设计赛先生或小赛的核心形象。
- 在 3D、2D、摄影、杂志或信息图风格之间随机切换。
- 训练或微调图片模型。
- 自动把新生成图片加入批准身份素材库。
- 前端生产部署、公开社交平台发布、ACR/流水线账户开通。
- 用无界随机数规避重复，或通过无限生成调用追求差异。

## Key Product Decisions

- 保留统一的 3D 卡通风格，只变化场景、构图、镜头、角色组合和主题物体。
- 配图文字统一为“`赛先生科学` + 类别主标题 + 类别短副标题”的三层深蓝圆角卡片，不允许模型
  自由增加文字；它与统一 3D 形象共同构成默认品牌标准。
- 采用最近七个自然日的受控去重，不要求身份参考轮换。
- 近重复最多触发一次不同视觉计划的重新生成；第二次仍近似时继续使用安全图片并记录 `diversity_warning`，保持全自动推送。
- 没有待用户确认的阻塞产品问题。
