# 科技教育优先与智谱排序兼容修复

## Goal

修正真实运行中暴露的两个问题：教育部来源不能因为属于宽泛“科技教育”主题就自动突破选题阈值；智谱排序也不能因为非关键解释字段不符合本地严格结构而丢弃一份本可安全使用的候选排列。新策略只优先实质性的科技教育政策、课程教学、人才培养和科技前沿教育实践，并将模型权限收窄为对固定候选 ID 做完整排序。

## Confirmed evidence

- 2026-08-20 本地真实选题运行中，`教育对口支援西藏工作会议暨教育系统援藏干部人才座谈会在拉萨召开` 的确定性总分为 `0.439`，低于 `0.59`，但因来源元数据与宽泛科技教育 cohort 命中 `ministry-education-priority-v3` 而突破阈值并入选。
- 同一轮排序只调用智谱一次；候选池为 8 条，供应商返回可解析响应但未通过当前严格结果 schema，系统记录 `invalid_provider_output` 并按设计回退到确定性顺序。原始供应商正文未持久化，因此不得猜测或依赖某一种未经证明的错误响应形态。
- 当前 `.9` 评分、`ministry-education-priority-v3` 和 `topic-rerank-v3-layered-auto-finalize` 已被运行快照引用，必须保持历史精确回放。
- 智谱官方 `json_object` 契约只保证生成 JSON；字段结构仍需在提示词中约束并由客户端验证，不能当作服务端 JSON Schema 保证。

## Requirements

### R1 — 收紧教育部优先语义

- 新建不可变的教育部优先规则版本，不修改 v3 历史行为。
- 只有来源已认证、策略元数据正确、无 hard veto，且内容属于实质性的科技教育政策/行动、课程教学、人才培养或科技前沿教育实践时，才可获得优先级或阈值突破。
- 仅有“会议、座谈会、论坛、发布会、教育援助”等活动形态，而缺少明确科技教育政策或实践内容时，不得优先。
- 普通教育行政、招生培训、消费促销、体育同形词等不得借科技关键词进入优先组。
- 航天回收、人工智能、机器人等一般硬科技新闻仍按高召回池和确定性/LLM 排序竞争；没有认证教育部策略时不得伪装成教育部优先。
- hard veto 永远高于优先规则。

### R2 — 新评分版本与历史回放

- 新建当前评分版本，将新教育部优先规则与现有 `.9` 的阈值 `0.59`、delivered-repeat、hard-tech pool 和 hard veto 组合起来。
- `.6`、`.7`、`.8`、`.9` 及 v3 优先规则的元数据往返、指纹和运行回放不得变化。
- 配置、Compose、示例环境和 Doctor 使用新当前版本；持久化运行仍按自身快照解析。

### R3 — 智谱最小排序协议

- 新建不可变 rerank 策略版本，不修改 v1/v2/v3 的提示词、payload、解析或回放。
- 新版本只要求模型返回固定候选池中 event ID 的完整排列；模型不得生成候选、修改 event/version、分数、eligibility、hard veto 或优先级屏障。
- 客户端接受一个经过明确版本化、严格有界的最小 JSON wire shape；不得用任意递归遍历、模糊字段猜测或从自然语言中提取 ID。
- ordinal、原因码和安全说明由本地根据冻结候选与最终排列确定性生成，不再依赖供应商解释字段。
- 仍使用 `response_format={"type":"json_object"}`、关闭 thinking/采样、温度为零，且每次决策最多一次模型调用。
- 未知、重复、缺失、额外 ID、跨优先级排列、非 JSON、超时或供应商错误仍确定性回退，不得触发第二次修正调用。

### R4 — 自动终审、审计和隐私

- 现有自动终审继续校验完整候选集合、event/version 绑定、eligibility、空 veto、优先级屏障、数量上限和 slot 同日排除。
- 审计继续记录策略版本、prompt/request 指纹、base/final order、typed outcome/failure、用量与延迟；不记录原始供应商响应、全文、密钥或私有路径。
- 公共 API 与下游文案、图片、OCR、企业微信状态机保持不变。

### R5 — 有界真实兼容确认

- 确定性测试和静态门全部通过后，允许执行一次隔离的智谱兼容确认：固定脱敏候选、`max_attempts=1`、不写业务数据库、不创建选题/文案/图片/交付任务。
- 成功只证明新 wire 契约与当前供应商兼容；失败只记录 typed failure 和安全用量，不保留原始响应，且不得重试。

## Acceptance Criteria

- [x] 西藏教育援助会议样例在新版本下 `priority_applied=false`，且 `0.439 < 0.59` 时不能突破阈值。
- [x] 明确的科技教育政策/行动方案、AI/机器人课程教学或科技人才培养实践仍可获得教育部优先。
- [x] 普通教育活动、招生促销、体育/消费同形词不能获得优先；hard veto 不能被优先覆盖。
- [x] `.9` + `ministry-education-priority-v3` 与 rerank v1/v2/v3 的元数据、指纹、prompt/payload/parser 和回放保持不变。
- [x] 新排序协议只接收完整 event ID 排列，并在本地生成稳定 ordinal、原因码和说明。
- [x] 新协议对未知/重复/缺失/额外 ID、跨优先级和非 JSON 输出只调用一次并确定性回退。
- [x] 日常与 slot 自动终审、审计、API 投影以及 provider-free eval 均通过；不改变下游发布链路。
- [x] 如执行真实兼容确认，调用次数精确为一次，且无数据库、抓取、文案、图片或交付副作用。

## Out of Scope

- 重新抓取新闻、重放 2026-08-20 选题、补发或生产部署。
- 改动文案、图片、OCR、公众号/企业微信发布链路。
- 让 LLM 判定事实真伪、解除 hard veto、改变分数或执行第二次 judge/correction 调用。
- 为兼容未知供应商形态而接受自然语言、任意嵌套 JSON 或不完整候选列表。
