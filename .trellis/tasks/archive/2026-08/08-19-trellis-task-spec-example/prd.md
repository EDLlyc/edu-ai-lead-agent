# Trellis 任务规范示例

## Goal

从 Trellis 简介 PDF 中删除两张项目运行截图及其证据页，改为一个不依赖截图的“真实任务 + 规范”简化示例，直观说明 Trellis 如何把任务目标、项目规则和交付结果连接起来。

## Confirmed Facts

- 当前报告为 6 页，第 5 页使用了两张 Agent Workbench 的真实运行截图；用户明确表示这不是想要的展示方式。
- 已归档的 `08-19-trellis-introduction-brief` 是本报告本身的真实任务，具有 `prd.md`、`design.md`、`implement.md`、`result.md` 等完整结构。
- `.trellis/spec/guides/index.md` 是当前项目真实的规范入口，包含“修改前先搜索”等工程思考指引。
- 这些任务与规范文件足以展示 Trellis 的工作方式，无需屏幕截图、服务运行或外部资源。

## Requirements

### R1 — 移除不合适的运行截图页

- 删除第 5 页中的两张 Agent Workbench 图片、图片依赖、caption 与 deterministic-fixture/loopback 相关叙述。
- 报告恢复为 5 页，不再引用 `docs/portfolio/runs/agent-workbench/...`。
- 不修改任何截图源文件、作品集文件或历史证据任务。

### R2 — 展示一个真实但简化的 Trellis 例子

- 使用“`Trellis 简介分享`”这个真实任务作为结构示例，但不展示内部路径、开发者身份、Git SHA、会话记录或用户业务内容。
- 页面至少展示：
  - Task：目标、需求/验收、设计/执行、结果；
  - Spec：项目规则在动手前被读取；
  - Output：可检查的交付物和验证结果。
- 采用排版化卡片/小流程图，而不是原始文件截图或终端截图。

### R3 — 简洁、准确的表达

- 将例子明确标为“基于真实任务结构的简化示意”，避免读者误把它当成所有任务的固定模板。
- 说明任务文件的多少会随复杂度变化；简单工作不一定需要全部文档。
- 保留原报告中 Trellis 与 Git、AI 模型、测试/评审的职责边界，以及“适合的工作 / 不该期待的事”。

### R4 — 验收与边界

- 不运行服务、浏览器、模型或外部工具；只改报告和本任务文件。
- XeLaTeX 成功编译，PDF 为 5 页，示例卡片清晰、文本可提取且无明显溢出。
- 不包含凭据、私有路径、内部业务数据或不必要的任务元数据。
- 除报告 TeX/PDF 和本任务文件外，不修改其他文件；现有用户改动保持不动。
