# Real task and spec structure used for the simplified example

## Real task basis

The archived `Trellis 简介分享` task contains:

- a PRD: goal, requirements, acceptance criteria and boundaries;
- a design note: narrative, page structure, visual and validation design;
- an implementation checklist: content, LaTeX/PDF and validation steps;
- a result note: delivered files and verification evidence.

The report should refer to these as four kinds of records, not expose their original paths, task ID, author, commit, or session data.

## Real spec basis

The local `.trellis/spec/guides/index.md` presents project thinking guides and a pre-modification rule: search for a value before changing it. The report can safely summarize this as “动手前读取项目规则，确认边界与已有做法”.

## Presentation contract

- Title: “一个真实任务，怎样连接规则与结果”.
- Label: “基于真实任务结构的简化示意”.
- Task card: “目标 / 需求与验收 / 设计与执行 / 结果记录”.
- Spec card: “项目规则 / 先确认范围 / 使用已有约定”.
- Output card: “可编辑源 / 成品 / 编译与检查记录”.
- Footnote: “任务会按复杂度保留必要工件，简单事项可以更轻。”

No screenshot, command, raw file content, internal path or task metadata is needed for this explanation.
