# 数字员工公众号自动推文方案调研：报告设计

## 1. Deliverables

- `reports/wechat-official-account-digital-employee-research-2026-08-17.tex`
- `reports/wechat-official-account-digital-employee-research-2026-08-17.pdf`

LaTeX 是可编辑源，PDF 是老师直接阅读的交付件。报告预计 10--14 页，以业务判断、方案对比和落地建议为主。

## 2. Evidence Strategy

资料按以下优先级使用：

1. 微信开放文档、微信公众平台官方说明；
2. 代表性产品的官网、帮助中心和官方操作指南；
3. 必要时使用可信行业资料补充市场背景，但不用于替代产品能力的一手证据；
4. 当前项目能力仅引用仓库已实现并有规范记录的事实，不引用线上密钥、服务器数据或未公开业务信息。

所有易变化的信息写明检索日期。价格若不是理解方案所必需，则不写具体金额；若写价格，必须注明页面日期和版本，不据此做长期预算承诺。

## 3. Report Narrative

报告按“先回答问题，再展开证据”的顺序组织：

1. **封面与执行摘要**：一句话结论、推荐方向、预期价值；
2. **任务理解**：数字员工不是完全无人值守，而是让机器处理重复工作、让人负责判断与签发；
3. **公众号自动推文工作链**：选题、采集、写作、配图、排版、审核、发布、复盘；
4. **现成方案版图**：
   - 公众号编辑与排版工具；
   - AI 内容生产工具；
   - 多账号协同与分发平台；
   - 工作流/数字员工定制方案；
5. **代表方案比较**：微信官方能力、135 编辑器、壹伴、新榜小豆芽，以及经一手资料确认的补充方案；
6. **三种可选路线**：人工增强型、半自动协同型、定制数字员工型；
7. **我们已有基础**：权威信源采集、选题治理、文案/配图、审核和可追溯记录；
8. **推荐方案**：先“自动生成到草稿 + 人工审核”，验证后再考虑受控发布；
9. **分阶段试点**：2 周准备、2--4 周试运行、稳定后再扩展；
10. **风险与治理**：事实、版权、平台权限、账号安全、品牌口径、AI 幻觉和效果评估；
11. **结论与来源**。

## 4. Comparison Framework

代表方案统一按以下维度比较，避免营销式罗列：

- 覆盖环节；
- 上手难度；
- 团队协同；
- 公众号适配程度；
- 人工审核能力；
- 多账号能力；
- 品牌定制空间；
- 账号与内容风险；
- 适用阶段。

不做虚假的精确打分。采用“强 / 中 / 弱 / 需定制”或简短说明，并在表下解释判断依据。

## 5. Recommended Operating Model

推荐采用“人机协同”的受控闭环：

```text
任务与栏目规划
  -> 权威资料收集
  -> AI 生成选题与初稿
  -> 配图与公众号排版
  -> 事实 / 版权 / 品牌人工审核
  -> 同步至公众号草稿箱
  -> 授权人员确认发布
  -> 阅读与互动数据复盘
```

第一阶段不主张无人审核自动群发。自动化优先替代资料整理、初稿、格式转换和数据汇总等重复工作；标题、事实、版权和最终发布由明确责任人签发。

## 6. Visual Design

- 沿用现有报告的 BrandNavy / BrandBlue / BrandGreen / BrandOrange 配色；
- A4、中文 Noto CJK 字体、页眉页脚、目录和来源链接；
- 使用 1 张端到端流程图、1 张方案版图、2--3 张对比表和若干结论框；
- 不使用依赖外网加载的图片，保证离线编译；
- 控制每页信息密度，避免长段技术解释。

## 7. Validation

- `latexmk -xelatex -interaction=nonstopmode -halt-on-error` 至少两遍收敛；
- `pdftotext` 检查正文、中文和来源是否存在；
- `pdffonts` 检查字体嵌入；
- `mutool draw` 或 PDF 页面截图抽查封面、目录、流程图、宽表和最后一页；
- 检查日志中的 overfull/underfull、missing glyph、undefined reference；
- 对所有产品能力和关键结论回查一手来源；
- 扫描 PDF/TeX，确保无密钥、服务器地址、私人路径和内部账号信息。

## 8. Boundaries

本任务只交付调研与汇报材料，不调用公众号接口，不绑定账号，不发送草稿或推文，不改动现有业务系统。
