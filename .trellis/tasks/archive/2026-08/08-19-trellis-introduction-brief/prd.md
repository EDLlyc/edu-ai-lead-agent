# Trellis 简介分享

## Goal

制作一份简短、易讲解的中文 PDF，用 5 分钟左右向同事或领导说明 Trellis 是什么、解决什么问题、基本工作流程以及它在 AI 辅助开发中的价值。报告只做概念介绍，不写成安装手册或内部实现文档。

## Background

- Trellis 将 AI 开发过程中容易散落的需求、规范、任务状态、检查结果和跨会话记录放回项目仓库，形成可持续的协作流程。
- 当前项目已经实际使用 `.trellis/workflow.md`、`.trellis/tasks/`、`.trellis/spec/` 和 `.trellis/workspace/`，可作为不含业务隐私的结构示例。
- 用户希望“简单讲讲”，因此报告应优先回答“它有什么用”，而不是罗列命令、平台适配或底层运行机制。

## Requirements

### R1 — 简单准确地定义 Trellis

- 用一句话说明：Trellis 是放在项目仓库里的 AI 开发协作框架，用统一流程连接需求规划、项目规范、任务执行、质量检查和经验沉淀。
- 不把 Trellis 描述成大模型、代码生成器、项目管理 SaaS 或会替代 Git 的工具。
- 说明它的核心价值是让 AI “先读规则、按任务工作、留下可复核记录”，提高连续性和可控性。

### R2 — 讲清基本工作流程

- 用一张简图呈现：提出需求 → 规划任务 → 加载项目规范 → 实现 → 检查 → 提交与归档 → 经验进入后续会话。
- 只解释关键节点，不展示长命令、脚本源码或状态机细节。
- 强调 Git 仍负责版本管理，Trellis 负责补充 AI 协作所需的流程与上下文。

### R3 — 介绍核心组成

- 用通俗语言介绍四类内容：
  - Workflow：规定开发阶段和下一步动作；
  - Tasks：保存某项工作的目标、设计、执行计划和结果；
  - Specs：保存项目自己的工程规范；
  - Workspace / Memory：保存跨会话的进展与经验。
- 多智能体协作、Channel 和 `trellis mem` 只作为进阶能力简要提及，不占据主体篇幅。

### R4 — 给出直观使用示例

- 使用不含真实业务数据的示例：提出“增加一个功能”后，Trellis 如何让 AI 先规划、读取规范、实现、检查并归档。
- 对比没有流程约束时常见的遗忘上下文、重复沟通、规范漂移，与使用 Trellis 后的可追踪工作方式。
- 不声称 Trellis 能自动保证代码正确，也不夸大效率提升幅度。

### R5 — LaTeX/PDF 交付

- 新建独立文件：
  - `reports/trellis-introduction-brief-2026-08-19.tex`
  - `reports/trellis-introduction-brief-2026-08-19.pdf`
- 使用 A4 中文排版，目标 4--5 页，适合屏幕阅读和简短分享。
- 至少包含一个生命周期流程图、一张核心组成表和一个简化使用场景。
- 图表使用离线可编译的 LaTeX/TikZ，不依赖外部在线素材。
- 不包含真实密钥、服务器信息、私人路径、内部业务数据或未公开对话。

## Acceptance Criteria

- [ ] PDF 为 4--5 页，5 分钟左右可以讲完。
- [ ] 封面或首页给出准确的一句话定义和一句话价值说明。
- [ ] 正文讲清“是什么、为什么需要、怎样工作、由什么组成、适合什么场景”。
- [ ] 至少包含一张生命周期流程图、一张核心组成表和一个简化案例。
- [ ] 明确 Trellis 与 Git、AI 模型的边界，不作“自动保证质量”等夸张承诺。
- [ ] 高级能力只用一小段介绍，不展开 Channel 协议、平台矩阵或 CLI 命令全集。
- [ ] XeLaTeX 编译成功；PDF 中文可复制，字体嵌入，无明显溢出、缺字或未定义引用。
- [ ] TeX/PDF 敏感信息扫描与 `git diff --check` 通过。
- [ ] 不改业务代码、不访问服务器、不调用外部模型、不部署服务。
- [ ] 保留当前工作区中所有用户已有修改和删除状态。

## Out of Scope

- Trellis 安装教程、命令参考手册或插件开发教程。
- 修改 `.trellis/` 工作流、Spec、Skill、Agent、Hook 或平台配置。
- 介绍 Trellis 上游源码、npm 包内部实现或完整多平台兼容矩阵。
- 对 Trellis 与其他框架做市场化排名或性能对比。
- 修改、提交或恢复现有业务报告和业务代码。

## Key Decisions

- 采用“概念 + 流程 + 结构 + 小案例”的讲解方式，不采用功能清单式宣传。
- 以当前项目内的 Trellis 文件和本地架构说明作为权威依据，不依赖易变化的网络资料。
- 报告目标为 4--5 页；若排版可以在 4 页内保持清晰，则不为了页数增加内容。
- 视觉上沿用项目报告的简洁蓝紫配色，但不复刻复杂封面或加入无关装饰。

## Open Questions

无。默认受众为对 AI 辅助开发有基本了解、但不了解 Trellis 的同事或领导。
