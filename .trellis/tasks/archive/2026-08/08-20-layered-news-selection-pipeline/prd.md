# 分层新闻筛选与自动终审流水线

## Goal

把现有新闻选题链路明确整理为“硬规则 → 高召回粗筛 → LLM 细筛 → 最终自动规则”的分层方案：硬规则只负责不可越过的真实性与安全边界，粗筛尽量保留有价值候选，LLM 在有界候选池内判断新闻价值并排序，最终阶段再执行确定性自动终审。目标是减少优质硬科技新闻被过早过滤，同时不让模型绕过证据、重复、时效和安全要求。

## Confirmed facts

- 当前采集只使用受控来源，已经具有来源版本、证据等级、时效、治理状态和可审计过滤原因。
- 当前 `scoring-v1-preview.9-broad-hard-tech-pool` 已将硬科技采集改为高召回，并保留未核验、无合格证据、Tier-C-only、陈旧、近期正式推送重复、隐私法律安全和欺骗性营销等 hard veto。
- 当前 topic selection 已具有确定性评分和可选的有界 LLM rerank：模型最多接收 8 个已 eligible 候选，只能在同一优先级分组内重排，不能移除 veto、修改分数或创造证据。
- 当前 LLM rerank 默认关闭，策略为 `topic-rerank-v2-zhipu-json-contract`，失败时保持确定性顺序并落审计记录。
- 当前文案、配图和企业微信交付链路已经具有规则校验、`review_required` 状态和人工审核接口；企业微信发送配置默认要求审核，自动交付另有独立开关。

## Requirements

### R1 — 第一层：硬规则

- 在任何模型调用前执行来源、证据、治理、时效、重复、隐私/法律/安全和欺骗性营销校验。
- hard veto 结果不可被数值评分、LLM 或人工排序逻辑覆盖。
- 每个拒绝结果保留稳定原因码和版本身份。

### R2 — 第二层：高召回粗筛

- 在 hard veto 通过后，以受控主题、基本相关性和宽松阈值形成有界候选池。
- 已完成突破、计划/试验、失败/复盘、融资/市场、会议/发布会和产品发布可以保留，但必须保留真实内容类别。
- 普通消费、体育/同形词、招生培训促销和无明确目标主题的财经/活动内容不得仅靠关键词混入。
- 粗筛不决定最终发布，只负责减少遗漏并输出可解释的基础分、类别和证据摘要。

### R3 — 第三层：LLM 细筛

- LLM 只接收经过治理且通过硬规则的精简候选投影，不接收完整文章、秘密、内部路径或不必要的个人信息。
- LLM 评估新闻价值、突破程度、时效性、传播价值、与受众/品牌的匹配度和候选间差异，输出严格有界的排序和原因码。
- LLM 不得修改 eligibility、hard veto、证据绑定、确定性分数、优先级屏障或候选集合。
- 无效输出、超时或供应商错误必须确定性降级，不得造成无选题或重复调用风暴。

### R4 — 第四层：最终自动规则与审计

- LLM 输出后自动复核同一不可变候选快照：候选集合、event/version 绑定、eligibility、空 veto、优先级屏障、完整排列、数量上限和 slot 同日排除。
- 持久化边界继续校验租约、配置指纹、日期/profile 锁和数据库唯一/FK 约束；不得为了“终审”重新抓取网页或读取漂移的当前默认配置。
- 该选题链路不设置人工审核；最终状态明确区分模型排序已应用、确定性降级和自动 `no_topic`。
- 模型降级时使用确定性基础顺序继续自动复核，不能进入等待人工的状态。
- 发布和补发仍由既有交付状态机控制，不在选题模型调用中直接触发。

### R5 — 不可变配置与审计

- 四层策略分别拥有不可变版本/快照；历史跑次按其持久化配置回放，不读取当前默认值重解释。
- 持久化候选进入/退出每一层的原因、确定性基础顺序、LLM 最终顺序、降级原因和自动终审状态。
- 日志只记录安全投影，不记录全文、原始供应商响应、密钥或私有路径。

## Acceptance Criteria

- [x] 一个来源合格、证据治理完成但分数较低的硬科技计划/失败/融资候选能够通过高召回粗筛并进入有界 LLM 池。
- [x] 未核验、陈旧、Tier-C-only、近期已正式推送重复或存在隐私法律安全风险的候选在模型调用前被拒绝，且模型调用次数为零。
- [x] LLM 只能重排传入候选，无法添加候选、跨优先级屏障、移除 veto 或改写证据绑定。
- [x] LLM 无效输出/超时会保留确定性顺序，记录稳定降级原因，并继续最终规则阶段。
- [x] 模型后的自动终审拒绝跨运行结果、event/version 不匹配、候选集合漂移、优先级越界和 slot 同日冲突；合法结果或确定性降级均可自动完成。
- [x] 每个最终结果可追溯四层版本、输入摘要、基础顺序、模型顺序、原因码和自动终审状态。
- [x] 历史评分与 rerank 配置保持精确回放；不进行生产部署、补发或真实供应商调用。

## Out of Scope

- 增加任意网页搜索、未审来源或开放式抓取。
- 让 LLM 直接决定事实真伪、解除安全 veto、生成 SQL/代码或直接发送消息。
- 调整文案生成、配图生成、OCR 或企业微信发送实现本身。
- 修改文案、图片或企业微信既有人工审核/直发配置；“不需要人工”仅适用于本任务的新闻选题流程。
- 本任务中的生产部署、历史重放、手工补发和真实供应商调用。

## Technical notes

- 现有 `.9` scoring、hard veto、高召回候选池和 v2 rerank 已覆盖前三层的大部分能力。本任务优先复用并补齐自动终审绑定，不复制一套评分器或引入第二次模型评审。
- 当前 LLM rerank 是显式开关；新分层策略应有新的不可变 rerank 身份，并在内容流水线启用时要求 `fake` 或 `zhipu` provider。安全的全局开发默认仍允许整个 content stage 关闭。
