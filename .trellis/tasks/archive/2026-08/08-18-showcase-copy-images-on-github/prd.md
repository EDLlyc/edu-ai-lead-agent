# 在 GitHub 首页展示文案与配图

## Goal

在 GitHub 仓库首页直接展示系统真实生成、且能由本地素材包证明一一对应的文案与配图，让招聘方不只看到流程截图，也能直观看到内容生产结果。

## Confirmed Evidence

本地存在两组适合作品集展示的完整素材包。二者均满足文案校验通过、文案审计接受、图片生成成功、图片校验通过，且图片文件 SHA-256 与素材包记录精确一致：

1. **科学教育“做中学”**
   - 业务日期：`2026-08-08`
   - 选题：`全国义务教育阶段科学教育“做中学”领航行动部署会召开`
   - 图片 SHA-256：`120295d1743380b584239c385dfd93266d7b30c850c3e98291cd9e3f7a29b9af`
   - 生成链路：智谱 `glm-5.2` 文案 + Comfly `gpt-image-2` 配图
2. **脑机接口与人工智能**
   - 业务日期：`2026-08-10`
   - 选题：`脑机接口技术借AI实现脑活动转文字`
   - 图片 SHA-256：`ee5eb2848163a30597a51820ed2e5b4728a022e5366fd721f6531fc3b0cef653`
   - 生成链路：智谱 `glm-5.2` 文案 + Comfly `gpt-image-2` 配图

两组文案均是面向公开传播的成品文本；展示时不得包含内部品牌知识原文、数据库 ID、对象存储路径、私有资料文件名或 provider 凭据。

## Requirements

- GitHub README 新增简洁的“真实内容产出”区域，每组展示配图、主题、简短说明和指向完整案例的链接。
- 新增 `docs/portfolio/content-showcase.md`，按“选题—配图—完整文案—验证信息”的顺序展示两组内容。
- 将两张经过核对的原始 PNG 复制到 `docs/portfolio/assets/content-showcase/`，使用中性英文文件名；不重新生成、不压缩改写内容，也不调用模型。
- 只公开成品文案和安全的生成/验证摘要；不复制完整素材包 JSON 或内部证据、品牌知识片段与私有路径。
- 发布前验证图片 SHA-256、Markdown 相对链接、README 渲染入口、秘密/私有路径扫描和 GitHub fast-forward 条件。
- 仅更新私有 GitHub 仓库 `main`；不改变可见性、不启用 GitHub Pages、不推送 Codeup、不部署服务器。
- 保留用户当前未提交的两份 `reports/**` 修改，不纳入此次提交或 GitHub 推送。

## Acceptance Criteria

- [ ] README 可以直接看到两张配图及各自主题，并能进入完整案例页。
- [ ] 完整案例页展示两组完整文案与对应配图，配对关系和 SHA-256 可复核。
- [ ] 两张发布图片与原始素材包记录的 SHA-256 精确一致。
- [ ] 页面不包含内部品牌知识原文、数据库/对象存储标识、凭据或私有绝对路径。
- [ ] GitHub `main` 通过 fast-forward 包含展示提交，远端 README 和两个图片资产可由 GitHub API 读取。
- [ ] GitHub 仓库保持 `PRIVATE`、Pages 保持关闭，Codeup 与生产环境不发生变化。
- [ ] 用户的未提交报告修改保持未暂存、未提交、未推送。

## Out of Scope

- 重新调用智谱、Comfly 或其他供应商生成新文案/图片。
- 从生产服务器、数据库或 MinIO 获取新的业务素材。
- 对文案做事实改写、营销增强或重新审核。
- 建设独立网站、开启 GitHub Pages 或将仓库改为公开。
