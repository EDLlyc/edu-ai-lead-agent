# Bug analysis: preview success is not production-path compatibility

## 1. Root cause category

Categories B (cross-layer contract), C (change propagation) and D (test coverage gap).
The original production incident combined a disabled generated-body branch and a simpler
prepared exporter, so successful Article/draft states did not imply contextual new illustrations
or local-layout parity. During strict integration, a generic multimodal image-count consumer
and the existing 2,000-character prompt boundary also exposed assumptions not exercised by
small isolated policy tests. Final-byte normalization is another independent boundary:
reviewing a preview crop does not validate the different actual upload thumbnail.

## 2. Why partial fixes were insufficient

- Enabling generation alone would not add durable final-upload audits or use the accepted renderer.
- Good isolated images do not prove the normal Article constructor, five-slot validation,
  repository readiness, new weekly input and prepared consumer agree on one identity.
- Short prompt fixtures passed while normal V10 block context overflowed the existing limit.
- Omitted-null golden bytes passed with a wrap serializer, but its dictionary return annotation
  collapsed the closed public response schema. Field-level omission and real FastAPI schema
  assertions are needed in addition to byte-golden tests.
- Repository tests that promote a primed legacy fixture test persistence edges, but not normal
  strict creation. They must be complemented by a material-package-to-prepared path.
- Main's suspected generated-caption mismatch was disproved by tracing the actual exporter:
  it deliberately uses immutable Article captions. The correct action was a regression documenting
  that choice, not a new schema or a speculative runtime fix.

## 4. Systematic expansion

Search and test every consumer when adding a versioned count, nullable identity field, schema
head or asset derivative: API/runtime constructors, generic validators, SQL constraints,
serializers, resolver, weekly retries, prepared consumer and operational doctor. Preserve frozen
golden hashes, and test null/unknown inputs explicitly; SQL CHECK UNKNOWN is not rejection.

Keep three evidence levels separate: a component succeeds, the normal assembled workflow
succeeds, and the actual production job reaches its intended terminal state. No lower level
may stand in for a higher one. A single historical latency sample is not a future SLA.
