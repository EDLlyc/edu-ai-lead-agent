# 企业微信自建应用单销售分发适配

## Goal

将已经通过文案验证、审计和图片校验，并且已经人工审核通过的素材包，异步发送给企业微信组织内一个固定销售员工。前端只负责查看素材包、创建发送任务和查看投递状态；系统不自动发布朋友圈或其他社交平台。

## Background

- 现有 `material_packages` 已经保存选题、完整朋友圈正文、来源、品牌绑定、审计快照和私有 MinIO 图片。
- 现有 content worker 负责生成素材包，不应在模型/图片生产阶段直接调用企业微信。
- 当前 API 没有企业微信配置或发送能力；企业微信凭证只能由服务端读取。
- 企业微信官方接口要求先获取应用 `access_token`，图片消息需要先通过临时素材接口上传图片取得 `media_id`，再调用应用消息接口。

## Requirements

### R1. 配置和安全边界

- 支持自建应用所需的 `CorpID`、`AgentID`、`CorpSecret` 和一个固定员工 `userid` 的服务端配置。
- API 和前端只使用内部 `recipient_id`，不接受或返回原始 `userid`；第一版唯一值为 `default`，显示名也由配置提供。
- `access_token` 仅保存在 dispatcher 进程内存中，不能写数据库、日志或 API 响应；凭证不得出现在异常文本中。
- `WECOM_AUTO_DELIVERY_ENABLED` 默认关闭。开启时也只允许发送到配置的固定员工，且仍要求素材包人工审核通过。

### R2. 投递 API

- 提供收件人列表接口、创建投递任务接口、投递详情接口和受控重试接口。
- 正式投递只能引用一个已经完成且 `review_status=approved` 的版本化素材包；失败不修改新闻、选题、文案或图片。
- 创建接口使用稳定幂等指纹；同一素材包版本、收件人和模式不创建第二条任务。
- API 创建任务只写入数据库并返回 `202`，不在请求中调用企业微信或读取图片。
- 详情接口只返回业务状态、消息子状态、尝试次数和安全错误码，不返回 token、原始供应商响应、临时 `media_id` 或 MinIO 内部信息。

### R3. 持久化和状态

- 新增企业微信投递任务和投递尝试表，使用 PostgreSQL 作为唯一状态源，并通过 Alembic 迁移创建。
- 任务状态至少支持 `queued`、`running`、`partial`、`delivery_unknown`、`delivered`、`failed`、`cancelled`。
- 文本和图片分别保存子状态，支持文字成功后只补发图片。
- dispatcher 使用 `FOR UPDATE SKIP LOCKED`、租约、心跳和有限重试；服务重启后未完成任务可恢复。
- 明确的 token 失效、限流和暂时不可用可以有限重试；网络超时导致服务端结果未知时进入 `delivery_unknown`，不能自动重复发送。

### R4. 企业微信发送行为

- 使用官方 HTTPS 接口获取 token、上传临时图片素材和发送应用消息。
- 发送文字消息时包含选题标题、完整朋友圈正文和标签；图片作为独立图片消息发送。
- 图片发送前从私有 MinIO 读取并校验 PNG/JPEG/WebP、大小和摘要；企业微信上传使用官方支持的 JPG/PNG，必要时拒绝不支持格式并提示人工处理。
- 启用官方重复消息检查参数，避免明确重复请求在检查窗口内重复下发。
- 只允许企业微信应用向内部员工发送，不实现回调、模板卡片、H5、公网入口或朋友圈自动发布。

### R5. 自动化运维

- 增加独立 `wecom-dispatcher` Compose 服务，默认通过 `wecom` profile 启动且配置开关关闭时不发送。
- dispatcher 可自动发现已经审核通过且尚未投递的素材包，但只有显式开启自动发送配置后才创建正式任务。
- 记录安全的 provider 错误码、消息类型、尝试次数、延迟和 provider request id；不记录响应正文和敏感请求头。

## Acceptance Criteria

- [ ] 配置缺失、`AgentID` 非法或企业微信关闭时，API 不创建发送任务，并返回稳定的配置/冲突错误。
- [ ] 未审核、审核拒绝、文案未 accepted、图片未 succeeded 的素材包不能创建正式投递。
- [ ] 相同素材包版本、收件人和模式重复提交只得到同一个 `delivery_id`，不会新增 job。
- [ ] 使用 HTTP mock 可以验证 token 获取缓存、token 失效刷新、图片 multipart 上传、文字/图片消息 JSON 和官方错误码映射。
- [ ] dispatcher 的成功路径会按文字、图片顺序发送，并把任务置为 `delivered`；文字成功图片失败时为 `partial`，重试只发送失败子任务。
- [ ] 传输超时进入 `delivery_unknown`，不会由 worker 自动盲发第二次；明确限流/临时错误按有限次数退避。
- [ ] 迁移、API、dispatcher 和单元/契约测试通过；Compose 配置能构建并启动 dispatcher（无真实凭证时保持禁用）。
- [ ] 生产日志和 API 响应中不存在 `CorpSecret`、`access_token`、原始 `userid`、`media_id` 或临时图片地址。

## Out of Scope

- 自动发布到个人微信朋友圈、企业朋友圈或其他社交平台。
- 多收件人管理、通讯录同步、回调验签、模板卡片、H5 操作页和企业微信会话内容存档。
- 在企业微信中重新生成文案/图片或改变已经锁定的选题。

## Open Questions

无阻塞问题。第一版固定单员工、人工审核后发送和默认关闭自动发送已确定。
