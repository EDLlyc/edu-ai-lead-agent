# 视觉多样性生产启用与单条验收

## Goal

在不产生企业微信发送、不污染生产素材记录且严格限制付费调用的前提下，用一条已经通过
文案治理的真实新闻完成受控视觉多样性 v2 的真实供应商验收；只有验收通过后，才在生产
环境同时启用视觉多样性与图片 OCR，使后续自然产生的新闻图片按新的 3D 品牌标准运行。

## Background

- 生产已经运行提交 `7d8a9142d3195ce5d0df8e62252a74d99229a1bc` 和 Alembic
  `20260815_0021`，受控规划、标题卡、OCR 顺序、一次近重复修复和审计表均已部署。
- `IMAGE_ENABLED=true`，真实图片供应商为 Comfly，结构化/OCR 供应商为智谱；当前
  `IMAGE_DIVERSITY_ENABLED` 与 `IMAGE_OCR_ENABLED` 均使用默认 `false`。
- 生产有九条“文案已接受、图片成功、未创建企微任务”的历史素材，可作为隔离验收输入；
  不需要重新选择新闻或重新生成文案。
- 直接重试旧图片会沿用旧预留，不能证明 v2；直接等待下一次生产栏目可能同时生成 1--3
  张并进入自动投递，因此都不满足本任务边界。

## Requirements

1. 启用前必须记录生产服务、数据库、图片/计划/相似度/企微计数以及 `.env` 校验值，并保存
   可恢复的 `.env` 副本。不得输出或复制任何密钥、令牌、Webhook、私有对象路径或原始提示词。
2. 验收必须使用生产数据的隔离克隆和独立私有 MinIO bucket；不得在生产数据库中为验收创建、
   删除或改写素材、图片、计划、相似度或投递记录。
3. 从一条已有 accepted copy、成功历史图片且无企微任务的真实新闻中确定性选择最新合格输入。
   隔离库只移除该输入的旧 v1 包/图片，使当前代码重新预留一个完整 v2 包；不得重新调用文案模型。
4. 验收期间停止生产 WeCom dispatcher，并暂停生产 content scheduler/worker。隔离运行显式关闭
   WeCom 与调度，只允许目标素材进入图片 worker。
5. 付费边界为最多两次图片生成和每张图片最多一次 OCR；验收禁用额外质量审计并将 artifact
   尝试上限收紧为 2。不得以重试循环、第三张图片或另一个新闻绕过失败。
6. 通过标准必须同时满足：一份独立素材包、一份成功图片、1024×1024、安全媒体校验、角色与
   新闻主题匹配、两个不同的受控计划预留、最终计划 ordinal 为 1 或 2、OCR 严格按顺序只识别
   `赛先生科学`、允许的类别标题和匹配短副标题、相似度决策为 `accepted` 或允许的
   `accepted_with_warning`，且不存在第三次生成。
7. 验收结果必须由操作者实际查看最终图片，确认标题卡没有遮挡角色面部、科学物体或主动作，
   没有伪文字、原始新闻标题、自由口号、二维码、水印或额外品牌标记。
8. 只有全部验收门通过后，才在生产 `.env` 中原子设置
   `IMAGE_DIVERSITY_ENABLED=true` 和 `IMAGE_OCR_ENABLED=true`，先验证 Compose/Settings，
   再重建 acquisition API 与 content worker，并恢复 content scheduler。
9. 恢复 WeCom dispatcher 前必须证明生产企微任务/尝试计数未变化、无非终态投递、无新的验收
   包或验收图片进入生产库。恢复后做稳定性采样，禁止手动 enqueue、retry 或 resend。
10. 若隔离验收失败，必须保持/恢复两个生产开关为 false，恢复原服务，不启用不完整能力；保留
    脱敏失败代码和有界调用计数，不删除任何生产历史。若生产启用后的 Settings、健康或稳定性门
    失败，则恢复 `.env` 副本并只重建受影响服务。

## Acceptance Criteria

- [ ] 启用前生产基线、`.env` 备份及零运行任务/零非终态投递门通过，日志和输出无秘密。
- [ ] 隔离数据库与 bucket 能证明与生产连接/对象命名分离，且只选择一条合格新闻。
- [ ] 隔离验收不调用文案生成，不创建企微 job/attempt，图片 artifact 调用次数不超过 2。
- [ ] 最终图片和持久审计满足 Requirement 6 的全部机器门，并通过 Requirement 7 的人工视觉检查。
- [ ] 验收通过后生产两个开关同时为 true；API/content worker 解析完全一致、使用目标镜像、
  运行健康且 restart count 为 0。
- [ ] 生产 durable counters 除后续自然业务调度外没有验收造成的变化；企微任务/尝试无验收增量。
- [ ] 30 秒稳定性采样无服务重启、未知投递或运行任务残留，最终回滚路径仍可执行。
- [ ] 若任何验收门失败，最终生产开关保持 false，服务恢复健康，并明确报告失败阶段与后续建议。

## Out of Scope

- 不调整选题、信源、文案、三时段或企微业务规则。
- 不发送测试或正式企微消息，不创建社交平台发布能力。
- 不增加图片供应商调用次数，不因验收失败换新闻重试。
- 不修改生产数据库历史，不启用图片质量审计，不部署前端。
- 不处理 ACR/Flow、发布工具或生产 Doctor 的其他改进。

## Deferred Items

- 生产启用通过后的七个业务日场景覆盖、近重复率、延迟与成本观察属于后续运营观察，不扩大本次
  单条验收预算。
- 若供应商无法稳定渲染严格中文标题卡，本任务失败关闭；文字策略或供应商变更需要新的产品决策。
