# 运营后台：系统内置词

关键词页上半部分是「系统内置词」。文案里出现这些词，这一稿就不通过。

能改的只有两类：

- **营销承诺**，例如「保证提分」「最权威」。
- **焦虑话术**，例如「输在起跑线」。

改完点「保存内置词」。从下一场选题开始按新词检查。已经开始的选题仍用保存前的那一版，所以改词不会改到正在写的稿。

「载入系统原版」只是把草稿填回代码里的原词，还要点保存才会生效。和当前生效的词完全一样时，保存会被拒绝。两类都可以删空。删空之后，这一类不再拦文案。

下面这些不能在页面上改，只能改代码：提示词注入、不安全画面、代操作微信，以及手机号、身份证号、邮箱的识别。页面上能看到它们，保存不会改到它们。

在系统内置词之外另加的关注词、屏蔽词、文案禁用词，还是这一页下半部分，各存各的版本。

生产上，`acquisition-api` 用 `.release.env` 里的 `APP_IMAGE`。`content-worker` 和 `content-scheduler` 是另一层镜像，只多了读这些词、并在开场时记下版本的文件。不要对这两个服务执行不带镜像覆盖的 `compose up`，否则它们会改用 `APP_IMAGE`，配置会和现在不一致。
