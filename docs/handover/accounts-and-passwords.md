## 后台里的两种角色

| 角色            | 能做什么                                                                           |
| --------------- | ---------------------------------------------------------------------------------- |
| 所有者（owner） | 全部。包括账号管理、模型配置、公众号账号、操作记录。                               |
| 编辑（editor）  | 新闻源、关键词、系统内置词、新闻审核、人工加推、发布、排版模板，以及「我的账号」。 |

规则：

- 所有者不能停用或降级自己；最后一个所有者也不能被停用。
- 用户名不会被重用，停用的账号会保留用户名。
- 创建账号和重置别人的密码，只有所有者能做。
- 改密码、停用账号，都会让这个账号已有的登录全部失效。

## 给新同事建账号

所有者登录后：「系统 → 账号管理」→ 新建，填用户名、显示名、角色。

密码有两种：

- 留空：系统生成一个 14 位的密码，**只显示一次**，复制后当面或用安全的方式给他，让他登录后自己在「我的账号」里改掉。
- 自己填：只保存加密后的结果，页面不会再显示。

不要通过聊天工具发密码。

## 登录有效期

登录一次有效 12 小时，过期要重新登录。展厅的大屏一天会掉线两次，需要有人重新登录。

## 服务器登录

服务器只用密钥登录，不用密码，配置里关闭了密码登录。

- 地址 `124.222.207.221`，用户 `ubuntu`，本机别名 `edu-ai-production`。
- 现在这把密钥在开发机上：`/root/.ssh/edu-ai-production`。
- **不要把私钥发给别人。** 两个人共用一把私钥，出事时查不出是谁，也没法单独撤掉其中一个人。

给接手的人开通的正确做法：

1. 他在自己电脑上生成一把新密钥，只把**公钥**（`.pub` 文件）发给你。
2. 你把公钥加到服务器 `ubuntu` 用户的 `~/.ssh/authorized_keys` 里。
3. 他确认能登录后，你再删掉旧的那一条公钥。

登录时报 `Connection closed by … port 22`，说明服务器在验密钥之前就断开了，常见原因是来源地址被拦或被封，换密钥没有用。处理见 [交接文档](../operations/handover.md)。

## 哪些密钥放在哪里

名目和交接表在 [交接文档](../operations/handover.md) 第 3 节。密钥本身只在两个地方，**不要写进仓库、聊天或文档**：

| 内容                                                    | 放在哪                                                                        |
| ------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 企业微信机器人、公众号密钥、模型接口密钥、数据库密码    | 服务器 `/opt/edu-ai-lead-agent/.env`，以及各平台控制台                        |
| 公众号密钥、模型密钥（在后台里录入的那份）              | 数据库里加密保存，页面上只显示 `••••1234` 这样的尾号                          |
| 加密这些密钥用的 `MODEL_SECRET_KEY`、`ADMIN_SECRET_KEY` | 服务器 `.env`。**丢了它们，数据库里加密的密钥就解不开，只能在后台重新录入。** |

后台录入的密钥优先于 `.env` 里的同名配置，所以核对时两处都要看。
